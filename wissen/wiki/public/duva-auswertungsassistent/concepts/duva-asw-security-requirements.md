# DUVA ASW Security Requirements

Based on the currently ingested DUVA source set, the ASW successor must satisfy a baseline of information-security requirements derived from procurement intent and the referenced operating/documentation context.

For implementation and acceptance, the required security baseline is:

- ISMS alignment: the ASW project must be embedded in an ISMS process with defined responsibilities and governance checkpoints.
- Risk-based development: security requirements must be identified, assessed, and maintained over the full lifecycle (planning, implementation, operation, and change).
- Secure software engineering controls: development and deployment must follow software-focused controls (for example requirements handling, secure design/implementation, and release safeguards) as represented by IT-Grundschutz CON.8 and APP.6 context pages.
- Access and authorization protection: ASW functions and data access must be role-based and least-privilege, especially for publication/export paths into information portals.
- Traceability and auditability: changes, evaluations, and output publication actions should be traceable to support verification, review, and incident analysis.
- Continuity and resilience readiness: operation of ASW should include continuity planning and recovery considerations consistent with broader security governance.

The DUVA pages in this corpus describe product and rollout context, while concrete control catalogs are represented by the linked BSI standards/bausteine pages.
